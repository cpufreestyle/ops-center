## 3. 作品简介（约 300 字，可直接粘贴）

统计局、政府内网的值班人员每天要在监控、备份、资产台账和变更记录之间来回切换。原始告警重复、备份是否超时需要人工判断、资产风险分散在表格里，交接班又依赖手工整理。真正影响值班效率的，不是"没有数据"，而是数据没有被组织成可执行的事项。

「运维值班台」不替换现有系统，而是把告警、备份、资产和交接班串成一个值班闭环：按主机+服务+标题合并告警并保留次数与最高级别；按日备/周备双阈值判断备份时效；对资产台账执行证书到期、责任人缺失、无备份、单机多关键服务检查；最后自动生成一页交接班。

升级版「全能工作台」在此之上加入 Agent 工作台：值班员用自然语言问"本班必须处理什么/哪些备份超时/为什么这条是阻断/证书快到期了吗/生成交接班"，Agent 自动调用对应工具并展示调用轨迹，每条结论标注引用了哪条证据——规则引擎出事实，AI 只做组织，不编造数字；重启、执行命令等越权请求一律拒绝并说明只读边界。

演示数据中：6 条原始告警合并为 5 条事件；4 个备份任务全部识别出时效异常（含 1 项无成功记录、最长 244.7 小时未成功）；16 项资产统一搜索并发现多类风险。

## 4. 核心亮点（3–5 条，按表单字数取舍）

1. **Agent 自己调工具，不是文案生成器**：9 个只读工具 + 8 步 tool loop，每个回答附工具调用轨迹与证据字段，杜绝 AI 幻觉数字。
2. **值班视角，不是大屏**：终点是事项被确认、处理、交接，全程审计留痕（确认动作写 ops_audit.jsonl，Agent 每步写 agent_audit.jsonl）。
3. **只读接入、数据不出域**：CSV/导出文件接入，不登录不执行不改现有系统；默认安全降级模式无需 API key，内网离线可跑，可切本地模型。
4. **轻，1–2 天可装**：单文件 Python 服务 + 浏览器 UI，另有 Kindle 白底看板。
5. **安全边界明确**：越权请求（重启/执行命令/批量确认）一律拒绝并解释只读边界，方案第七节 7 条验收用例全部通过（含 2 条拒绝）。

## 5. 解决的问题 / 使用场景

- 场景：政府/事业单位信息中心（如统计局）的日常值班、交接班、周报。
- 痛点：告警重复噪声大、备份是否超时靠人记、资产风险散在表格里、交接班靠手工整理。
- 结果：值班员看到的是"现在必须处理什么、为什么、交给谁"，而不是一堆原始数据列表。

## 6. Agent / AI 能力说明（Agent 赛道重点）

- **架构**：四层——数据与规则层（复用 ops_center.py 纯函数）→ 工具层（agent_tools.py，9 个 JSON Schema 工具薄包装）→ Agent 调度层（agent_loop.py，单会话 ≤8 步 tool loop，写审计）→ 界面层（ops.html「小浣熊」对话 tab）。
- **工具清单（只读，可自动调用）**：get_overview、list_findings、get_finding_detail、list_alerts、check_backup_status、search_assets、check_data_quality、get_handover、get_recent_changes。
- **生成类（输入必须来自工具）**：交接班解读/问答、8 页 PPT 大纲、≤200 字值班摘要。
- **写动作（必须人工确认）**：ack_finding（建议确认，人点按钮才落库）、export_handover（导出文件）。明确不做：登录设备、执行命令、改配置、重启服务。
- **可插拔模型**：默认安全降级（模板化组织，无 API key、离线可演示）；设 OPS_LLM_BASE_URL 即升级为 OpenAI 兼容端点自由生成。
